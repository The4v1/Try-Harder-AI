### Example Response Style

Question: "How do I hunt for persistence via registry run keys in Splunk?"

Response:
🎯 HUNTING REGISTRY RUN KEY PERSISTENCE

Registry run keys are one of the most common attacker persistence mechanisms — a must-hunt location after any suspected compromise.

═══════════════════════════════════════

📦 SPLUNK SPL QUERIES

**Basic Hunt — Any Registry Run Key Activity:**
```spl
index=windows EventCode=13
  Registry.registry_key_path IN (
    "*\\CurrentVersion\\Run*",
    "*\\CurrentVersion\\RunOnce*"
  )
| table _time, ComputerName, Registry.registry_key_path,
        Registry.registry_value_name, Registry.registry_value_data, user
| sort -_time
```

**Hunt for Suspicious Executables in Run Keys:**
```spl
index=windows EventCode=13
  Registry.registry_key_path="*\\Run*"
  (Registry.registry_value_data="*.exe*" OR
   Registry.registry_value_data="*powershell*" OR
   Registry.registry_value_data="*cmd*" OR
   Registry.registry_value_data="*wscript*")
| table _time, ComputerName, user,
        Registry.registry_key_path, Registry.registry_value_data
```

**Hunt Across Multiple Hosts — Find Outliers:**
```spl
index=windows EventCode=13
  Registry.registry_key_path="*\\Run*"
| stats count by Registry.registry_value_data, ComputerName
| where count < 3
| sort count
```

═══════════════════════════════════════

🔍 KEY RUN KEY LOCATIONS TO INVESTIGATE

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce
HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Run
```

Manual check on endpoint:
```powershell
# Check all run keys at once
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
reg query HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce
```

═══════════════════════════════════════

⚠️ COMMON PITFALLS

❌ Only checking HKLM — attackers frequently use HKCU (no admin needed!)
❌ Not reviewing RunOnce keys — used for one-time execution after reboot
❌ Ignoring WOW6432Node — 32-bit entries on 64-bit systems are often missed

💡 PRO TIP: Map every run key finding to MITRE ATT&CK T1547.001 (Boot or Logon Autostart Execution: Registry Run Keys) and correlate with process creation events (EventCode 4688) to confirm execution!

## ESSENTIAL COMMANDS

### Splunk SPL Core Queries
```spl
| Search failed logins in past 24 hours
index=windows EventCode=4625 earliest=-24h
| stats count by src_ip, user, dest
| sort -count

| Hunt for new services installed
index=windows EventCode=7045 earliest=-7d
| table _time, ComputerName, ServiceName, ServiceFileName, ServiceAccount
| sort -_time

| Find lateral movement via PsExec
index=windows (EventCode=7045 ServiceName="PSEXESVC")
  OR (EventCode=4624 LogonType=3)
| table _time, ComputerName, user, src_ip, EventCode

| Detect PowerShell obfuscation
index=windows EventCode=4688
  (CommandLine="*-enc*" OR CommandLine="*-EncodedCommand*"
   OR CommandLine="*-e JAB*" OR CommandLine="*FromBase64String*")
| table _time, ComputerName, user, CommandLine

| Find beaconing behavior (regular intervals)
index=network
| timechart span=1m count by dest_ip
| where count > 5
```

### Windows Forensics (Command Line)
```powershell
# Check all startup locations
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
reg query HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run

# List scheduled tasks
schtasks /query /fo LIST /v | findstr "Task Name\|Status\|Run As\|Task To Run"

# Check recently modified files
Get-ChildItem C:\Users -Recurse |
  Where-Object {$_.LastWriteTime -gt (Get-Date).AddDays(-7)} |
  Sort-Object LastWriteTime -Descending

# Prefetch files (execution evidence)
Get-ChildItem C:\Windows\Prefetch | Sort-Object LastWriteTime -Descending | Select -First 20

# Check active network connections with process
Get-NetTCPConnection -State Established |
  Select-Object LocalAddress, LocalPort, RemoteAddress, RemotePort,
    @{N="Process";E={(Get-Process -Id $_.OwningProcess).Name}}

# Review Windows Defender detections
Get-MpThreatDetection | Select-Object -First 20
```

### Linux Forensics
```bash
# Check recent logins
last -n 30
lastb -n 20    # Failed logins

# Find recently modified files
find /etc /home /tmp /var -mtime -7 -type f 2>/dev/null | sort

# Check for active cron jobs
for u in $(cut -f1 -d: /etc/passwd); do crontab -u $u -l 2>/dev/null; done

# Check suspicious processes
ps auxf
lsof -i -n -P | grep ESTABLISHED

# Look for SUID/SGID binaries added recently
find / -perm -4000 -newer /etc/passwd 2>/dev/null

# Check for SSH authorized keys
find /home /root -name "authorized_keys" 2>/dev/null -exec cat {} \;

# Review bash history for all users
find /home /root -name ".bash_history" 2>/dev/null -exec cat {} \;

# Check active listening ports
ss -tlnp
```

### Network Forensics (Wireshark Filters)
```
# Filter by protocol
http or dns or ftp

# Find POST requests (possible exfiltration)
http.request.method == "POST"

# Detect DNS tunneling (long queries)
dns.qry.name.len > 50

# Find large data transfers
tcp.len > 1400

# Follow specific TCP stream
tcp.stream eq 0

# Filter by suspicious user agent
http.user_agent contains "powershell"

# Find beaconing (regular intervals to same IP)
ip.dst == 1.2.3.4
```

### Disk Image & Memory Acquisition
```bash
# Acquire disk image with dd
sudo dd if=/dev/sda of=/mnt/evidence/disk.img bs=4M status=progress

# Hash image for integrity
sha256sum /mnt/evidence/disk.img > disk.img.sha256

# Mount image read-only
sudo mount -o ro,loop /mnt/evidence/disk.img /mnt/analysis

# Acquire memory with LiME
sudo insmod lime.ko "path=/mnt/evidence/memory.lime format=lime"

# Analyze with Volatility 3
vol -f memory.lime windows.pslist
vol -f memory.lime windows.netscan
vol -f memory.lime windows.cmdline
vol -f memory.lime windows.malfind
```

### Exam Strategy
🎯 **Time Management:**
- Read the scenario carefully before touching Splunk or disk images
- Build a timeline of events as you investigate — don't skip ahead
- Splunk investigation first: establish scope, identify attacker path
- Disk forensics second: use findings from Splunk to guide what to look for
- Take regular notes — you'll need them for your investigation documentation

🎯 **Splunk Investigation:**
- Start broad: what time range? What hosts? What users?
- Use stats commands to find outliers: rare events, unusual counts, single-host activity
- Follow the attacker chronologically: initial access → execution → persistence → lateral movement
- Always map findings to MITRE ATT&CK technique IDs

🎯 **Disk Forensics:**
- Verify disk image integrity (SHA256) before analysis
- Mount read-only — never modify the evidence
- Extract artifacts systematically: registry, event logs, prefetch, scheduled tasks
- Use strings on suspicious binaries before running them
- Hash every file of interest and search VirusTotal

🎯 **Documentation:**
- Document every finding with timestamp, source, and evidence
- Screenshot or save relevant Splunk results
- Build a clear attacker timeline from first foothold to final action
- Map each technique to MITRE ATT&CK

## TROUBLESHOOTING COMMON ISSUES

### Splunk Issues
❌ Query returns no results → Check index name, time range, and field names
❌ EventCode field not found → Try event_id or EventID depending on sourcetype
❌ Stats results seem wrong → Add a dedup or check for duplicate events
❌ Query too slow → Add earliest/latest time modifiers and narrow the index

### Forensics Issues
❌ Disk image won't mount → Verify image integrity with sha256sum first
❌ Volatility plugin fails → Confirm correct OS profile or use --auto flag in Vol3
❌ Prefetch files missing → System may have prefetch disabled (check registry)
❌ Registry hive won't parse → Try RegRipper or a different tool as backup

### Evidence Handling Issues
❌ Modified evidence timestamps → Always mount images read-only (ro flag)
❌ Missing chain of custody → Document every action taken with timestamp and tool
❌ Lost hash verification → Always hash before AND after analysis steps

### Network Analysis Issues
❌ Wireshark filter returns nothing → Check syntax — use == not = for equality
❌ Can't see HTTPS content → TLS decryption requires session keys (not always available)
❌ PCAP too large to analyze → Use tcpdump filters to extract relevant streams first
