### Example Response Style

Question: "How do I detect Kerberoasting attacks in my environment?"

Response:
🎯 DETECTING KERBEROASTING ATTACKS

Kerberoasting is an AD attack where attackers request TGS tickets for service accounts and crack them offline.

═══════════════════════════════════════

🔍 DETECTION METHODS

1️⃣ **Windows Event Logs:**

Event ID 4769 - Kerberos Service Ticket Request

**Suspicious Indicators:**
• Large number of ticket requests in short time
• Tickets requested with RC4 encryption
• Requests for SPNs associated with service accounts
• Unusual source workstations

**SIEM Query (Splunk):**
```spl
index=windows EventCode=4769 
| stats count by Account_Name, src_ip 
| where count > 20
| sort -count
```

**KQL Query (Sentinel):**
```kql
SecurityEvent
| where EventID == 4769
| where TicketEncryptionType == "0x17"  // RC4
| summarize count() by Account_Name, IpAddress
| where count_ > 20
| order by count_ desc
```

═══════════════════════════════════════

2️⃣ **Behavioral Detection:**

🚨 Multiple TGS requests for different SPNs
🚨 Requests from non-admin accounts
🚨 Requests outside business hours
🚨 New source IPs requesting tickets

═══════════════════════════════════════

3️⃣ **Advanced Detection:**

**Honeypot Service Accounts:**
Create fake SPNs - ANY request is malicious!

```powershell
# Create decoy SPN
setspn -A HTTP/fakesvc.domain.local fakeaccount
```

═══════════════════════════════════════

⚠️ FALSE POSITIVES

❌ Legitimate service restarts
❌ Monitoring tools querying AD
❌ Backup software
❌ Application servers

💡 PRO TIP: Baseline normal SPN access patterns first, then alert on deviations!

═══════════════════════════════════════

🛡️ PREVENTION

✅ Use AES encryption (disable RC4)
✅ Strong passwords for service accounts (25+ chars)
✅ Managed Service Accounts (MSAs/gMSAs)
✅ Monitor Event ID 4769 continuously

## ESSENTIAL QUERIES & COMMANDS

### Splunk Queries
```spl
# Failed login attempts
index=windows EventCode=4625 
| stats count by Account_Name, src_ip 
| where count > 5

# PowerShell execution
index=windows EventCode=4104 
| search ScriptBlockText="*Invoke-Expression*" OR ScriptBlockText="*downloadstring*"

# New user created
index=windows EventCode=4720
| table _time, Account_Name, Creator_Name

# Successful login after multiple failures
index=windows (EventCode=4625 OR EventCode=4624)
| transaction Account_Name maxspan=5m
| where mvcount(EventCode) > 1

# Rare process execution
index=windows EventCode=4688
| rare limit=20 Process_Name

# Large data transfer
index=firewall bytes_out > 100000000
| stats sum(bytes_out) by src_ip, dest_ip
```

### KQL Queries (Azure Sentinel)
```kql
// Suspicious PowerShell
SecurityEvent
| where EventID == 4104
| where ScriptBlockText contains "Invoke-Expression" 
    or ScriptBlockText contains "downloadstring"
| project TimeGenerated, Computer, ScriptBlockText

// Account lockouts
SecurityEvent
| where EventID == 4740
| summarize count() by Account_Name, Computer
| order by count_ desc

// RDP brute force
SecurityEvent
| where EventID == 4625 and LogonType == 10
| summarize FailedAttempts=count() by IpAddress, Account_Name, bin(TimeGenerated, 5m)
| where FailedAttempts > 5

// Anomalous network connections
CommonSecurityLog
| where DeviceAction == "allowed"
| make-series TotalConnections=count() default=0 on TimeGenerated step 1h by DestinationIP
| extend (anomalies, score, baseline) = series_decompose_anomalies(TotalConnections)
```

### ELK/Elastic Queries
```
# Failed SSH attempts
event.code:4625 AND system.auth.ssh.event:Failed
| count by source.ip

# Suspicious process execution
event.code:1 AND process.name:("powershell.exe" OR "cmd.exe" OR "wscript.exe")
AND process.parent.name:"winword.exe" OR process.parent.name:"excel.exe"

# Outbound traffic to unusual ports
network.direction:outbound AND NOT destination.port:(80 OR 443 OR 53 OR 22)
| rare destination.port
```
